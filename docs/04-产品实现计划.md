### 2.2 已解决的关键问题

| 问题 | 根因 | 解决方案 | 源码 |
|------|------|---------|------|
| 排序性能极差 | 缺少 COOP/COEP 头，SharedArrayBuffer 不可用 | Vite 配置跨域隔离头 | `vite.config.js` |
| 渲染帧率低 | DPR=2 + MSAA 开启 | 像素比 1.0 + antialias:false | `index.ts:303,308` |
| 双 RAF 冗余 | TourPlayer 独立 RAF + 渲染器 RAF | 通过 onFrame() 挂载到单一 RAF | `tour-player.ts:72` |
| 场景倒置 | Y-down → Y-up 坐标系差异 | 加载后 rotation.x = π | `index.ts:436` |
| 摄像机定位差 | 无自动定位逻辑 | getBoundingBox 中心定位 | `index.ts:555-601` |
| LOD 不生效 | 扁平 .splat 无 LOD 层级 | 显式 createLodSplats() | `index.ts:618-627` |
| 交互不自然 | OrbitControls 视差不自然 | DragLookControls 原地转头 | `index.ts:65-205` |
| 移动卡顿 | 固定步长累加器量化跳变 | 连续指数平滑 (exp(-dt/τ)) | `index.ts:710-769` |

## 3. 阶段二：渲染增强与数据工具（已完成）

### 3.1 目标

- 引入 WebGPU 渲染后端，实现 GPU Radix Sort（超大场景 5-10× 加速）
- 实现 SOG 流式 LOD，支持渐进式加载
- 提供数据转换 CLI 工具链
- 完善热点深度遮挡检测
- 扩展移动端多指触摸手势

### 3.2 任务分解

#### 3.2.1 WebGPU 渲染后端（2-3 周）

| 任务 | 说明 | 优先级 | 依赖 | 状态 |
|------|------|--------|------|------|
| WebGPU 能力检测 | `navigator.gpu` 检测 + WebGL2 回退 | P0 | — | ✅ 已完成 |
| SuperSplat 核心集成 | 提取 SuperSplat 的 GPU Radix Sort 逻辑 | P0 | 能力检测 | ⚠️ 未来增强 |
| WebGPURenderer 实现 | 实现 `RendererAdapter` 接口的 WebGPU 版本 | P0 | SuperSplat 集成 | ⚠️ 架构就绪 |
| 双后端自动切换 | WebGPU 优先，不可用时回退 WebGL2 | P0 | WebGPURenderer | ✅ 已完成 |
| WGSL Compute Shader | GPU 排序着色器 | P1 | SuperSplat 集成 | ❌ 未开始 |
| WebGPU 性能基准 | 对比 WebGL2 帧率 | P1 | 双后端切换 | ❌ 未开始 |

**技术方案**：
```
RenderManager (入口)
  ├── if (navigator.gpu && preferWebGPU)
  │     └── new WebGPURenderer()  ← SuperSplat 核心
  └── else
        └── new WebGL2Renderer()  ← Spark (当前实现)
```

**验收标准**：
- ✅ WebGPU 可用时自动检测，不可用时回退 WebGL2（`createRenderer()` 工厂函数）
- ⚠️ 1M splats 桌面端 60fps（WebGL2 Spark 已达标；WebGPU WGSL 渲染待 SuperSplat 集成）
- ❌ 10M+ splats WebGPU 下 ≥ 30fps（待 WGSL Compute Shader）

#### 3.2.2 SOG 流式 LOD（1-2 周）

| 任务 | 说明 | 优先级 | 状态 |
|------|------|--------|------|
| SOG 格式解析器 | 空间排序高斯格式解析 | P0 | ✅ 已完成 |
| 分块加载管理器 | 按视锥体和距离加载分块 | P0 | ✅ 已完成 |
| 渐进式渲染 | 首帧快速渲染，逐步补充细节 | P0 | ✅ 已完成 |
| 内存管理 | 远距离分块卸载，控制显存 | P1 | ❌ 未开始 |
| SceneConfig.lodSource | 配置 SOG 流式 URL | P0 | ✅ 已集成 |

**验收标准**：
- ✅ SOG 文件正确解析 header + chunk index（72,105 splats → 5 chunks 验证通过）
- ✅ 分块加载管理器支持顺序/并行加载（`SogStreamer` 类，HTTP Range 请求）
- ✅ `lodSource` 已集成到渲染管线（`RenderManager.loadScene()` 支持 SOG 流式加载，首帧快速渲染 + 渐进补全）
- ⚠️ 5M+ splats 场景首帧 < 2s（待大规模场景测试）
- ❌ 显存占用控制（待内存管理实现）

#### 3.2.3 数据转换 CLI（1-2 周）

| 任务 | 说明 | 优先级 | 状态 |
|------|------|--------|------|
| PLY → SPLAT 转换 | 32 字节/splat 格式 | P0 | ✅ 已完成 |
| PLY → SPZ 转换 | gzip 压缩, Niantic SPZ v2 格式 | P0 | ✅ 已完成 |
| PLY → SOG 转换 | 空间排序分块格式 | P0 | ✅ 已完成 |
| 冗余剔除 | 过滤低透明度/异常高斯核 | P1 | ✅ 已完成 |
| Morton Code 排序 | 空间排序加速首帧 | P1 | ✅ 已完成 |
| LOD 构建 | 分块 + 层级构建 | P1 | ⚠️ SOG 分块已实现, 层级 LOD 待完善 |
| 批量转换 | 并行处理多个场景 | P2 | ✅ 已完成 |
| 配置模板生成 | 一键生成 tour.json 模板 | P1 | ✅ 已完成 |

**CLI 设计**：
```bash
# 单文件转换
npx @3dgs/convert ply-to-spz input.ply --output output.spz --sh-degree 1

# 批量转换 + LOD
npx @3dgs/convert batch ./scenes/ --format spz --sh-degree 1 --lod

# 生成配置模板
npx @3dgs/convert generate-tour ./scenes/ --output tour.json
```

**验收标准**：
- ⚠️ PLY → SPZ 压缩比 ≥ 8×（SH 0 场景 3.85×，SH 1-3 场景可达 8×+，待高 SH 数据验证）
- ⚠️ 转换后视觉质量 PSNR ≥ 32dB（待自动化视觉回归测试）
- ✅ 批量转换支持多场景（`batch` 命令验证通过）
- ✅ 所有 CLI 命令验证通过（`info` / `ply-to-splat` / `ply-to-spz` / `ply-to-sog` / `batch` / `generate-tour`）

## 9. 风险管理

### 9.1 风险矩阵

| 风险 | 影响 | 概率 | 严重度 | 缓解措施 | 负责人 |
|------|------|------|--------|---------|--------|
| **COOP/COEP 部署限制** | SharedArrayBuffer 不可用，排序退化 10-30× | 中 | 高 | ① SW 代理方案 ② 降级路径 ③ 部署文档 | — |
| **iOS Safari WebGPU 延迟** | 移动端无法用 GPU 排序 | 高 | 中 | WebGL2 + WASM Worker 保底（已实现） | — |
| **Spark 维护中断** | 依赖断裂 | 低 | 高 | Fork 并维护内部版本；保持松耦合便于替换 | — |
| **SuperSplat 集成复杂度** | WebGPU 后端开发延期 | 中 | 中 | 先评估核心代码可提取性；预留 WebGL2 保底 | — |
| **超大场景内存溢出** | 移动端崩溃 | 中 | 高 | LOD Streaming + 设备预算表 + 内存监控 | — |
| **SPZ WASM 加载延迟** | 首屏加载慢 | 中 | 低 | 分块加载 + 渐进式解码 + 加载进度提示 | — |
| **WebGPU API 变更** | 渲染后端需适配 | 低 | 中 | 关注 W3C 规范进展；抽象层隔离 | — |
| **开源社区反应不及预期** | 采用率低 | 中 | 低 | 完善 文档+示例；积极推广；收集反馈 | — |

### 9.2 风险应对策略

#### COOP/COEP 部署限制（最高风险）

**影响**：Spark 的 WASM Worker 排序依赖 `SharedArrayBuffer`，未配置 COOP/COEP 时排序从 ~5ms 退化为 ~150ms，1M splats 帧率从 60fps 降至 ~7fps。

**应对措施**：
1. **短期**（阶段四）：完善部署文档，覆盖 Nginx / Vercel / Cloudflare / Apache 配置
2. **中期**（阶段五）：Service Worker 代理方案——SW 拦截请求注入 COOP/COEP 头
3. **长期**：探索不依赖 SharedArrayBuffer 的排序方案（如 GPU 排序）

#### Spark 维护中断

**影响**：如果 Spark 停止维护，3DGS 渲染能力受影响。

**应对措施**：
1. `RendererAdapter` 接口已抽象渲染后端，可替换为其他实现
2. Fork Spark 仓库，维护内部版本
3. 持续评估 GaussianSplats3D 等替代方案
