# 转换质量深度分析与优化方案

> **日期**: 2026-08-28
> **触发**: 用户反馈 `demo2.splat` 渲染质量远不如原始 `demo2.ply`
> **方法**: 转换管线代码审阅 → 渲染器（Spark）源码比对 → 逐属性数值对比（2000 采样/文件）→ 渲染路径分析
> **分析脚本**: `scripts/compare-quality.mjs`（可复现）

---

## 1. 结论摘要

| 问题 | 结论 |
|------|------|
| 转换是否损坏数据？ | ❌ **否**。三个文件逐属性对比均在 8-bit 量化极限内，无系统性偏差 |
| 质量差异的真正根源？ | **渲染端按设备分级的降采样策略不一致**：`.ply` 直载不截断，`.splat/.sog` 路径按 `maxSplats` 降采样 |
| 转换工具需要修什么？ | 已修复：SuperSplat 双重解析（garden 解析 34.8s→7.8s）；其余见 §5 方案 |

## 2. 数值保真度实测（源文件 → .splat 产物）

对 `demo1.ply`、`demo2.ply`、`garden.ply`（均为 SuperSplat 2.x 打包格式）按 2000 均匀采样逐属性对比：

| 属性 | demo1 (991K) | demo2 (3.97M) | garden (5.83M) | 性质 |
|------|-------------|---------------|----------------|------|
| 位置最大误差 | 0.001‰ | 0.001‰ | 0.002‰ | Float32 舍入，可忽略 |
| 缩放相对误差 | 0.0000% | 0.0000% | 0.0000% | 精确 |
| 旋转角度误差 | 平均 0.43° / 最大 0.81° | 平均 0.43° / 最大 0.81° | 平均 0.09° / 最大 0.63° | .splat 8-bit 旋转量化极限 |
| 颜色误差 | 平均 0.19 / 最大 0.47（/255） | 平均 0.21 / 最大 0.49 | 平均 0.16 / 最大 0.45 | ≤0.5/255 = 8-bit 舍入极限 |
| 不透明度误差 | 0 | 0 | 0 | 精确 |
| 颜色均值 | 源=产物（完全一致） | 源=产物 | 源=产物 | **无系统性偏移**（排除伽马/色彩空间 bug） |

**解读**：所有误差都恰好等于目标格式的量化下限（.splat 为 RGBA8 + 8-bit 旋转），说明转换管线**没有任何信息浪费之外的损失**。

### 2.1 与渲染器（Spark）的解码一致性

逐行比对 `loadSuperSplatPly` 与 Spark `decodeSuperSplat`（spark.module.js:13168-13253）：位置/旋转/缩放/颜色/不透明度五组解码公式**完全一致**。即：同一文件经我们转换与 Spark 直载，得到的数值数据等价。

### 2.2 格式固有限制（非缺陷）

- `.splat` 仅存 DC 颜色（无高阶 SH）与 8-bit 旋转 —— 对**含高阶 SH 的标准 3DGS PLY**，转 .splat 会丢失视角相关着色（本次三个源文件均为 SuperSplat 打包、无高阶 SH，不受影响）；
- SPZ 保留 SH（degree 0-3）；SOG 可选 `--sh-mode 1` 保留 SH DC。

## 3. 质量差异的真正根源：渲染端降采样不一致 ⚠️

**实测渲染路径对比**（同一场景不同格式在 demo 中的加载路径）：

| 格式 | 加载路径 | 数量限制 |
|------|---------|---------|
| `.ply` | `new SplatMesh({ url, maxSplats })` | Spark `maxSplats` 仅为**预分配提示，不截断** → 渲染**全量**（demo2 3.97M） |
| `.splat` | `loadSceneWithTruncatedSplat` | **均匀降采样**到设备档 `maxSplats`（LOW 250K / MEDIUM 500K / HIGH 1M / ULTRA 2.5M） |
| `.spz` | `loadSceneWithSpz`（原生） | **不降采样**（H1 已知权衡） |
| `.sog` | `SogStreamer` 早期终止 | 按 `maxSplats` 只加载前 N 个 Morton chunk |

**推演**（以 ULTRA 档 2.5M 上限为例）：
- `demo2.ply` → 渲染 3.97M（100%）
- `demo2.splat` → 渲染 2.5M（**63%**）
- `garden.splat` → 渲染 2.5M（**43%**）

这就是"转换后质量远不如原文件"的直接原因：**不是转换丢了数据，而是渲染的 splat 数量被设备策略裁掉了 37%~87%**。基准数据也印证：demo2 PLY 全量渲染仅 2.9 FPS（软件渲染），.splat 降采样后 60 FPS —— 该策略本意是性能保护。

## 4. 本次已实施的优化

### 4.1 SuperSplat 双重解析修复（耗时优化，已完成 ✅）

- **问题**：旧逻辑先对全文件跑通用快路径解析，发现是 SuperSplat 后丢弃结果、再用通用慢路径解析一遍；
- **修复**：头部判定后直接走新增的 `loadSuperSplatFastPath`（TypedArray 直解码，公式与慢路径/Spark 同源），不支持的变体自动回退慢路径；
- **实测**（解析阶段）：

| 文件 | 修复前 | 修复后 | 提速 |
|------|--------|--------|------|
| demo1.ply (991K) | 1.5s | 0.7s | 2.1× |
| demo2.ply (3.97M) | 6.1s | 2.5s | 2.4× |
| garden.ply (5.83M) | 34.8s | 7.8s | **4.5×** |

- 端到端 `ply-to-splat garden.ply`：**11.8s → 5.6s**；
- 新增 6 个专项测试（构造 SuperSplat PLY 验证位置/颜色/缩放/旋转/跨 chunk 解码），全部 483 测试通过。

## 5. 优化方案（按优先级，含耗时平衡）

### P1 — 消除感知质量落差（渲染端，0 转换耗时影响）

| # | 方案 | 说明 | 耗时影响 |
|---|------|------|---------|
| 1 | **降采样策略对齐** | `.ply` 直载路径目前不截断，与其他格式不可比。两选一：**A.** PLY 也走降采样（质量一致、性能可预期，但 Spark 无截断能力 → 需先 fetch 再降采样，加载变慢）；**B.** 提供"全质量模式"开关（`?full=1` 绕过降采样），默认保持性能保护 | A: 加载 +30~50%；B: 0 |
| 2 | **HUD 明示降采样状态** | demo HUD 显示"渲染 X / Y splats（设备档降采样）"，让质量差异可解释 | 0 |
| 3 | **文档警示**（✅ 本次已随方案补充到 README） | 大场景 .splat/.sog 按设备档降采样；需要全量质量时用 .ply 或提升设备档/覆盖 `maxSplats` | 0 |

### P2 — 转换工具质量增强（可控耗时）

| # | 方案 | 说明 | 耗时影响 |
|---|------|------|---------|
| 4 | **`--max-splats` 转换期预裁剪** | 转换时结合 Morton 排序取前缀（空间均匀），产物体积与渲染数量一次确定；渲染端检测到数量 ≤ 档位时不再降采样 → 所见即所得 | +5~10%（复用既有排序） |
| 5 | **`--prune` 策略推荐** | 剔除浮点噪声/低贡献高斯核，**观感质量提升**（去噪点/飞絮）；建议对含噪训练产物默认开启 | +10~15% |
| 6 | **SH 保留策略** | 标准高阶 SH PLY：优先 SPZ（自动保留全阶）或 SOG `--sh-mode 1`（保留 DC）；.splat 明示为"烘焙 DC"格式 | 0 |
| 7 | **转换产物质量回执** | `info` 命令输出各格式位深/量化参数与源对比，便于验收 | 0 |

### P3 — 结构性优化（排期）

| # | 方案 | 说明 | 耗时影响 |
|---|------|------|---------|
| 8 | **SoA 管线**（优化文档 §4.6） | 解析/写入全程列式 TypedArray，解除 5M+ 场景的 8GB 堆依赖，写入再提速 ~2× | 转换内存 -50%+，速度 +30~50% |
| 9 | **Worker 化转换** | 浏览器端/CLI 复用同一 WASM 或 Worker 池 | 交互场景不阻塞主线程 |

### 不建议实施（已排除）

- ~~伽马/色彩空间转换选项~~：数值对比证明无系统性偏移，SuperSplat 颜色已为烘焙值，加伽马反而引入错误；
- ~~提高 .splat 旋转精度~~：格式固定 8-bit，误差 ≤0.8° 对高斯椭球渲染不可见。
