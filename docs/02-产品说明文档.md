## 1. 产品愿景

### 1.1 使命

让任何开发者都能在 Web 端轻松嵌入和定制 3D 高斯溅射（3DGS）场景浏览体验，无需理解底层渲染技术。

### 1.2 愿景

成为 Web 端 3DGS 渲染与漫游领域的**开源标准方案**，提供极致的3DGS浏览体验，同时保持完全开源和高度可拓展。

### 1.3 设计哲学

| 原则 | 说明 |
|------|------|
| **轻量级** | 核心包零运行时依赖，按需加载，Bundle 体积最小化 |
| **高性能** | 桌面端 60fps，移动端 30fps，自适应分辨率保障流畅 |
| **高可拓展** | 插件化架构，一切领域功能（热点、相机控制等）均为插件 |
| **框架无关** | 核心 SDK 与前端框架解耦，提供 React/Vue 薄适配层 |
| **开箱即用** | 3 行代码嵌入 3DGS 场景，配置驱动，业务人员可操作 |

## 2. 目标用户与使用场景

### 2.1 目标用户

| 用户角色 | 需求 | 产品提供 |
|---------|------|---------|
| **Web 前端开发者** | 快速嵌入 3DGS 场景到现有应用 | React/Vue 组件，3 行代码集成 |
| **3D/VR 内容创作者** | 展示 3DGS 扫描场景，添加交互热点 | 配置驱动的漫游框架，热点系统 |
| **企业开发团队** | 构建行业解决方案（房产、博物馆、文旅） | 插件化架构，可定制扩展 |
| **开源社区贡献者** | 扩展引擎能力，贡献插件 | 清晰的插件 API，TypeScript 类型定义 |

### 2.2 典型使用场景

#### 场景一：房产虚拟看房

```
用户操作流程:
  1. 使用数据转换工具将 PLY 转为 SPZ 格式
  2. 编写 tour.json 配置文件定义场景拓扑和热点
  3. 嵌入 <TourViewer> 组件到网站
  4. 用户通过热点在房间间漫游，点击查看详情
```

#### 场景二：博物馆数字化展览

```
用户操作流程:
  1. 多个展厅 3DGS 场景转换为 SPZ
  2. 配置场景间跳转热点和展品信息热点
  3. 部署到 CDN，支持流式加载
  4. 游客在线漫游，点击展品热点查看介绍
```

#### 场景三：产品 3D 展示

```
用户操作流程:
  1. 单个产品 3DGS 模型转为 SPZ
  2. 嵌入到电商页面，用户拖拽旋转查看
  3. 自适应分辨率保障移动端流畅
```

### 3.2 核心价值主张

1. **不只是渲染引擎，更是漫游框架**——提供场景图管理、热点系统、过渡动画、配置格式等可拓展的交互能力。

2. **不自研渲染引擎，复用最优开源**——基于 Spark (WebGL2) + SuperSplat (WebGPU) 开源渲染方案，性能有保障。

3. **插件化一切**——热点、相机控制、自动旋转等均为独立插件，不需要的功能不会增加 Bundle 体积。

4. **配置驱动**——声明式 JSON 配置（类比 Krpano XML），业务人员可编辑，无需写代码。

5. **框架无关**——核心 SDK 无前端框架依赖，React/Vue 适配层各约 100 行代码。

### 5.2 设计原则

| 原则 | 说明 |
|------|------|
| **关注点分离** | 数据转换、渲染引擎、漫游框架、应用展示四层完全解耦 |
| **可替换性** | 渲染后端可替换（Spark ↔ SuperSplat ↔ 自研），数据格式可替换 |
| **渐进增强** | WebGL2 保底 + WebGPU 渐进增强 |
| **插件化** | 热点、相机控制、自动旋转等均以插件形式提供 |
| **零运行时依赖** | 核心包无 npm 运行时依赖，渲染引擎作为 peerDependency |

### 5.3 三层解耦设计

1. **渲染解耦**：`@3dgs/core` 不依赖渲染器，通过 `RendererAdapter` 接口与渲染层解耦。用户可自行实现接口替换渲染后端。

2. **热点解耦**：`@3dgs/core` 不包含热点逻辑。热点系统作为 `@3dgs/plugins/hotspot` 插件实现，通过事件总线和 `FrameContext` 与核心层交互。不注册热点插件即可获得纯 3DGS 查看器。

3. **配置解耦**：`SceneConfig` 使用通用 `extensions` 字段挂载插件配置，核心层不感知任何插件的配置 schema。

## 6. 集成方式

### 6.1 核心 SDK（无框架）

```typescript
import { TourPlayer } from '@3dgs/core';
import { RenderManager } from '@3dgs/renderer-three';
import { createHotspotSystem } from '@3dgs/plugins';

const player = new TourPlayer(document.getElementById('viewer'));
player.setRenderer(new RenderManager());
player.use(createHotspotSystem());

player.on('hotspot:click', (h) => console.log('点击热点', h));

await player.load({
  version: '1.0',
  scenes: {
    kitchen: {
      title: '厨房',
      source: '/kitchen.spz',
      extensions: {
        hotspot: {
          hotspots: [
            { id: 'info', type: 'text', position: [0.5, 1.2, -1.0] },
          ],
        },
      },
    },
  },
});

await player.switchScene('kitchen');
```

### 6.2 React 组件

```tsx
import { TourViewer } from '@3dgs/react';
import { RenderManager } from '@3dgs/renderer-three';
import { createHotspotSystem } from '@3dgs/plugins';

function MuseumTour() {
  return (
    <TourViewer
      config="/tours/museum.tour.json"
      renderer={() => new RenderManager()}
      plugins={[createHotspotSystem()]}
      onSceneSwitch={(id) => console.log('切换到', id)}
      onHotspotClick={(id) => console.log('点击', id)}
    />
  );
}
```

## 9. 配置系统

### 9.1 TourConfig 格式

TourConfig 是声明式 JSON 配置格式，定义整个漫游项目的场景拓扑、热点链接、默认参数，类比 Krpano XML。

```json
{
  "version": "1.0",
  "meta": {
    "title": "博物馆漫游",
    "description": "基于 3DGS 的全景漫游演示"
  },
```

## 10. 插件生态

### 10.1 官方插件

| 插件 | 功能 | 说明 |
|------|------|------|
| **HotspotSystem** | 热点系统 | 3D 锚定 + 2D HUD + 事件 + 场景跳转 + 自动预加载 |
| **CameraControls** | 相机控制 | 触摸手势 + 惯性 + 自动旋转 |
| **DepthOcclusion** | 深度遮挡 | PBO 异步深度读取，热点遮挡检测 |
| **SceneTransition** | 场景过渡 | 淡入淡出 / 飞行相机 / 即时切换 |
| **LoadingIndicator** | 加载进度 | CSS spinner + 进度百分比 |
| **Fullscreen** | 全屏模式 | requestFullscreen + 横屏锁定 |
| **AutoRotate** | 自动旋转 | 可配置速度/延迟 |

### 10.2 插件接口

```typescript
interface TourPlugin {
  name: string;
  version: string;
  init?(ctx: TourPluginContext): void;
  update?(ctx: FrameContext): void;
  destroy?(): void;
}
```

### 10.3 插件间通信

插件通过事件总线通信：
- 监听 `scene:switched` → 加载热点配置
- 监听 `hotspot:set-occlusion` → 注册遮挡检测回调
- 派发 `hotspot:click` → 通知应用层
